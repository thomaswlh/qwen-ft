# 参数速查：Megatron SFT → GRPO（Qwen2.5-0.5B + GSM8K）

装环境和包：见 [环境安装.md](环境安装.md)。

入口：

- SFT：`scripts/run_sft.sh`
- GRPO（SFT 热启动）：`scripts/run_grpo.sh`
- GRPO（官方 Instruct 对照）：`scripts/run_grpo_base.sh`

命令行临时改 Hydra 参数：`bash scripts/run_sft.sh optim.lr=2e-5`。永久改就编辑脚本。

前缀 `++` 表示往配置树**新增**原本没有的键。普通 `=` 是覆盖已有键。

## 环境变量（`scripts/env.sh`）

| 变量 | 默认 | 含义 |
|---|---|---|
| `CUDA_VISIBLE_DEVICES` | `2` | 用哪张 GPU |
| `CUDA_DEVICE_MAX_CONNECTIONS` | `1` | Megatron 通信与计算重叠 |
| `VLLM_USE_V1` | `1` | vLLM V1 引擎 |
| `VERL_USE_UV` | `0` | 不用 uv 拉起 |
| `NGPUS` / `TP` / `PP` / `SP` | `1` / `1` / `1` / `1` | 卡数与并行度。`DP = NGPUS / (TP*PP)` |
| `FULL_RECOMPUTE` | `0` | `recompute_granularity=full` |
| `FLASH` | `0` | `attention_backend=flash`，否则 `unfused` |
| `LORA` | `0` | `model.lora.rank=32` |
| `STEPS` | 空 | GRPO `total_training_steps` |
| `VLLM_GPU_UTIL` | `0.15` | 共享卡上给 vLLM 留的比例（0.3 在 80G 卡上约 24G，容易和别人抢爆） |
| `VERL_PYTHON` | 自动 | 强制指定解释器 |

本机 `qwen-ft`（torch cu130）和驱动 12.9 不兼容，且 `megatron.bridge` 导不进。脚本会回退到 `/home/jpzhao_team/zymo/verl_env`。

## SFT（`verl.trainer.sft_trainer` + `engine=megatron`）

必须用 `torchrun` / `torch.distributed.run`，trainer 启动就读 `torch.distributed.get_rank()`。

| 参数 | 本次值 | 含义 |
|---|---|---|
| `data.messages_key` | `messages` | verl 0.9 SFT 对话列 |
| `data.pad_mode` | `no_padding` | Megatron/FSDP SFT 都只支持这个 |
| `data.ignore_input_ids_mismatch` | `True` | Qwen chat template 拼 turn 长度可能对不齐 |
| `data.train_batch_size` | `16` | 全局 batch |
| `data.micro_batch_size_per_gpu` | `2` | 单卡微批，显存开关 |
| `data.max_length` | `1024` | 单条最长 token |
| `engine.tensor_model_parallel_size` | `TP` | 张量并行 |
| `engine.pipeline_model_parallel_size` | `PP` | 流水线并行 |
| `engine.sequence_parallel` | `SP` | 序列并行 |
| `engine.use_mbridge` | `True` | Megatron-Bridge |
| `engine.vanilla_mbridge` | `False` | 不用旧 mbridge（要 TE） |
| `engine.override_transformer_config.attention_backend` | `unfused` | 没装 flash_attn / TE |
| `++...masked_softmax_fusion` | `False` | PyPI megatron-core 常缺编译扩展 |
| `optim.lr` | `1e-5` | 小模型 SFT 常用 1e-5~2e-5 |
| `trainer.total_epochs` | `3` | smoke 可改 `1` |
| `trainer.save_freq` | `-1` | 只在结束存一次 |
| `checkpoint.save_contents` | 含 `hf_model` | 写出 HF 目录供 GRPO 加载 |

结束后软链：`output/latest_hf -> checkpoints/gsm8k_sft/global_step_*/model/huggingface`（Megatron-Bridge 把 HF 权重写在 `model/huggingface`）。

看什么：`train/loss` 从 ~1.x 掉到 0.3 附近；再用 `scripts/generate_sample.py` 看有没有 `#### 数字`。

## GRPO（`verl.trainer.main_ppo` + `ppo_megatron_trainer`）

Ray **不用手起**：`main_ppo` 单机本地起。0.5B 不需要多机调度。

| 参数 | 本次值 | 含义 |
|---|---|---|
| `algorithm.adv_estimator` | `grpo` | 组内相对优势，无 critic |
| `trainer.critic_warmup` | `0` | GRPO 不训 critic |
| `data.return_raw_chat` | `True` | 用模型 chat 模板包 prompt |
| `data.train_batch_size` | `32` | 每步 prompt 数 |
| `rollout.n` | `2` | 每个 prompt 采样数 = GRPO 组大小 |
| `actor.ppo_mini_batch_size` | `16` | 更新小批 |
| `actor.ppo_micro_batch_size_per_gpu` | `2` | 显存友好微批 |
| `actor.optim.lr` | `1e-6` | RL 学习率很小 |
| `actor.use_kl_loss` / `kl_loss_coef` | `True` / `0.01` | 防止偏离 ref |
| `rollout.name` | `vllm` | 生成引擎 |
| `rollout.gpu_memory_utilization` | `0.15` | 训推同卡 |
| `actor/ref.megatron.use_mbridge` | `True` | 与 SFT 同一套 bridge |
| `trainer.save_freq` | `1000` | 避免一步一个大 ckpt |
| `trainer.test_freq` | `1` | 每步验证，出 `reward/mean@1` |
| `trainer.total_epochs` | `2` | 512 条 / 32 = 16 步/轮 × 2 = 32 步 |

reward：`data_source=openai/gsm8k` → verl 内置规则，扫回答里的 `#### <数字>`。

看什么：`reward/mean@1`（验证答对率）、`actor/loss`、`kl_loss`、`response_length/mean`、`timing_s/*`。

旧项目经验：SFT 热启动初始 reward 大约 0.36，裸 Instruct 大约 0.17~0.23。8 步 smoke 只验证链路。

## 数据

两阶段 user 指令必须一致：

`Let's think step by step and output the final answer after "####".`

- SFT：`messages = [user, assistant]`，assistant 是清洗后的标准解法
- GRPO：`prompt` + `reward_model.ground_truth` + `data_source=openai/gsm8k`

默认 512 / 128。全量：`--train_samples 7473 --test_samples 1319`。

## 磁盘

- SFT HF 权重约 1GB 量级
- GRPO 每个 Megatron checkpoint 可能到数 GB；实验务必把 `save_freq` 调大，不用的 `checkpoints/<exp>/` 直接删

## 本机已知坑

1. `qwen-ft` 的 torch 是 cu130，驱动 12.9 → CUDA init 失败。用 `env.sh` 回退或换 cu128 的 torch。
2. `qwen-ft` 的 `megatron-core==0.12.3` 没有 `megatron.core.distributed.fsdp`，`megatron.bridge` 导不进。
3. 没装独立 `flash_attn` / Transformer Engine：默认 `unfused` + `masked_softmax_fusion=False`。
4. `pad_mode` 不能改 `right`。
5. 共享 GPU：`gpu_memory_utilization` 按整卡容量算，不是按剩余显存算。
6. 不要给 GRPO 设 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`，vLLM 会直接 assert。
7. Hydra 里 `ref.megatron.override_transformer_config.*` 新键必须用 `++`。

## 本次 smoke（2026-09-21，GPU2 A800 剩余约 22GB）

| 阶段 | 结果 |
|---|---|
| SFT | 1 epoch / 64 步（`batch=8, micro=1, max_length=768, FULL_RECOMPUTE=1`），约 3 分钟，peak 显存 11GB，`train/loss` ~4.3→3.8，`val/loss` 3.93 |
| SFT 生成 | 12 个苹果那道题输出多行 `####` 计算，最终 `#### 8 - 2 = 6`，格式检查通过 |
| GRPO | 8 步约 7 分钟（含启动）；初始 `reward/acc@1=0.0078`，结束 `0.0156`。8 步只验证 Megatron actor/ref + vLLM + Ray 链路 |

1 epoch SFT 还不够把采样 rollout 的 `####` 格式学稳，所以 GRPO 验证分很低是正常的。要刷分需要完整 3 epoch SFT，再把 GRPO 跑到 32 步以上。
